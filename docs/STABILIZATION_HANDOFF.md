# Stabilization Handoff: Azotus System Audit

This document is for **Code-Dex** to finalize the stabilization of the Azotus subtitle broadcast system.

## 1. Executive Summary of "The Mess"
The system currently suffers from **stalls** and **zombie processes**. The primary culprit is the process management layer (`start_omega.sh` and `stop_all.sh`). 

- **Zombies**: These scripts use `nohup` and PID files. If a script is restarted or the terminal closes, the Python workers (`omega_manager.py`) and Node servers (`next-server`) often survive in a "zombie" state. They hold database connections and file locks, causing new runs to fail silently or stall at the `INGESTING` or `BURNING` stages.
- **Pipeline Failure**: Just today, a bug in the new V2 Finalizer exporters (SRT/VTT) was discovered: newlines were being double-escaped as `\\n` instead of `\n`. This caused the FFmpeg burn filter to receive a malformed subtitle file, resulting in videos with **no subtitles**.

## 2. Recent Changes (Last 48 Hours)
- **V2 Finalizer Refactor**: Moved from a 2,500-line monolith (`workers/finalizer.py`) to a modular package in `workers/finalizer/`.
    - `models.py`: Dataclass-based `SubtitleEvent` for type safety.
    - `timing.py`: Strict broadcast timing constraints (Netflix/BBC standards).
    - `formatting.py`: Text cleaning and Icelandic Bible ref abbreviation.

- **FFmpeg Burn Hardening**: Configured `publish` in `workers/publisher.py` to render to a local `temp_render/` folder on the internal SSD first to prevent external USB drive IO saturation.
